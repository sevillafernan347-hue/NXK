# Reglas para colaborar en NXK

- Leer README.md, ESTADO.md, COLABORACION.md y PLAN-8-SESIONES.md antes de editar.
- Continuar el codigo existente. No regenerar el proyecto desde cero.
- Mantener comentarios y documentacion en espanol.
- Objetivo principal: BIOS x86, 32 bits, laptop de 1 GB. No importar el kernel Linux.
- Priorizar NEXTRY/NEXTRY ASM. Identificar los puentes C y las capacidades pendientes.
- Usar una rama y copia de trabajo propia por tarea. No cambiar de rama en la carpeta
  que otra sesion esta usando. No sobrescribir ni borrar cambios ajenos.
- La cuenta principal integra. Las otras sesiones preparan cambios para revision.
- No modificar contratos NXE, API, direcciones de memoria o ABI de otra tarea sin
  registrar la propuesta y obtener acuerdo del responsable de integracion.
- Antes de entregar cambios de kernel: compilar, probar x86 y documentar el resultado.
  Si faltan herramientas, indicarlo; nunca declarar pruebas que no se ejecutaron.
- No subir herramientas, libros, credenciales, discos generados ni claves.
- No prometer porcentajes comparados con Windows ni compatibilidad fisica sin pruebas.
